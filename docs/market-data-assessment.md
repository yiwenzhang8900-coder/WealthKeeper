# 行情数据评估

对应问题 1–4：各市场需要什么数据、能否自动获取、接口合法性与成本、存款理财低成本接入。

---

## 1. 各资产需要的行情数据

### A 股（股票 / 场内 ETF）

| 字段 | 用途 | 频率建议 |
|---|---|---|
| 最新价 / 收盘价 | 市值、当日盈亏 | 日终必须；盘中可选 |
| 前收盘 | 当日涨跌额/幅 | 日终 |
| 复权因子或后复权价 | 历史收益曲线一致性 | 日终 |
| 分红（现金分红、送转） | 累计收益中的分红部分 | 事件驱动 / 日更 |
| 交易状态（停牌、退市） | 避免错误估值 | 日更 |
| 币种 | CNY | 静态 |

**注意**：A 股有涨跌停、停牌；停牌日应用最近有效价并标记「非实时」。

### 港股

| 字段 | 用途 | 频率建议 |
|---|---|---|
| 收盘价 / 最新价 | 市值 | 日终必须 |
| 前收 | 当日盈亏 | 日终 |
| 分红、拆合股 | 收益与股数调整 | 事件驱动 |
| HKD→本币汇率 | 统一资产口径 | 日终 |
| 交易时段差异 | 与 A/美股对齐日切 | 配置 |

**注意**：港股报价单位多为港币；部分股票一手股数不同，但不影响市值计算（按股）。

### 美股 / 美股 ETF

| 字段 | 用途 | 频率建议 |
|---|---|---|
| 收盘价 / 最新价 | 市值 | 日终必须（注意盘后） |
| 前收 | 当日盈亏 | 日终 |
| 分红、拆股 | 收益与持仓调整 | 事件驱动 |
| USD→本币汇率 | 统一口径 | 日终 |
| 调整收盘价（adj close） | 历史对比 | 日终 |

**注意**：个人财富视图建议用「当地市场收盘价」做日切，并单独展示汇率损益（可选进阶）。

### 场内 ETF（各市场）

与对应市场股票类似，额外需要：

| 字段 | 用途 |
|---|---|
| IOPV / 净值（若有） | 折溢价参考（MVP 可不做） |
| 基金公司分红 / 拆分 | 收益归因 |
| 跟踪指数代码（可选） | 对比基准 |

MVP：**把 ETF 当可交易标的用收盘价估值即可**，不必先做折溢价。

### 场外基金（公募 / 货币 / 债基等）

| 字段 | 用途 | 频率建议 |
|---|---|---|
| 单位净值（NAV） | 市值 = 份额 × 净值 | 日更（T 日净值常 T+1 公布） |
| 累计净值 | 历史收益对比 | 日更 |
| 分红再投 / 现金分红 | 收益归因 | 事件驱动 |
| 申购赎回状态 | 提示不可交易日 | 日更（可选） |
| 货币基金份额万份收益 / 七日年化 | 货币基金展示 | 日更 |

**关键差异**：场外基金几乎没有「实时成交价」，应以 **官方净值** 为准；收益按净值日计算，接受 1 日滞后。

## 2. 哪些可以实时 / 每日自动获取

| 数据类型 | 自动程度 | 说明 |
|---|---|---|
| A/港/美 日终收盘价 | ✅ 每日自动 | MVP 主路径 |
| 场外基金净值 | ✅ 每日自动（常滞后 1 日） | MVP 主路径 |
| 汇率（USD/HKD/CNY） | ✅ 每日自动 | 统一本币必备 |
| 分红 / 拆股事件 | ⚠️ 半自动 | 接口覆盖不全时需用户补录 |
| 盘中实时报价 | ⚠️ 可选增强 | 成本高、合规严；个人复盘非刚需 |
| Level-2 / 逐笔 | ❌ 不做 | 贵且无必要 |
| 银行活期/定期余额 | ❌ 接口难 | MVP 手工录入余额与利率 |
| 银行理财/存款产品行情 | ❌ 无统一公开 API | 手工录入预期收益率或到期兑付 |

**结论**：股票 / ETF / 场外基金的 **日频估值可以全自动**；分红事件建议「自动优先 + 用户可改」；银行存款与多数理财 **先手工账户模型**。

## 3. 合法、稳定、成本可接受的接口策略

### 合规原则（个人自用 App）

1. **个人本地使用** 与 **对外分发/商用** 法律要求不同；若上架应用商店或服务他人，必须有可再分发授权的行情源。  
2. 免费爬虫类接口（部分东财/新浪聚合）适合 **原型与自用**，不适合作为长期商用唯一依赖。  
3. 展示行情时注明「数据仅供参考，不构成投资建议」，并遵守各源 ToS（禁止再分发、限流等）。

### 推荐分层（按阶段）

#### Phase A · 个人自用 / 原型（成本 ≈ 0）

| 市场 | 推荐 | 稳定性 | 合法性注意 |
|---|---|---|---|
| A 股 / 场内 ETF / 场外基金 | **AkShare** 或 **Tushare Pro**（积分够用） | 中；接口偶发变更 | AkShare 标明研究用途；Tushare 有明确协议与积分 |
| 港股 / 美股 / 美股 ETF | **yfinance**（Yahoo） | 中；有限流风险 | 非正式授权 API，适合自用 |
| 汇率 | 公开 FX 日终源 / yfinance / 央行中间价类接口 | 中高 | 选有明确来源的日终价 |

**Tushare Pro**：A 股基本面与日线较稳，免费积分有限，深度数据需积分或付费。  
**AkShare**：覆盖面广（含基金净值），零 Key，但依赖上游页面，长期稳定性一般。  
**yfinance**：美港方便，国内网络可能需代理。

#### Phase B · 可上架 / 多用户（成本可控）

| 用途 | 候选 | 大致成本感 |
|---|---|---|
| 美股/全球 EOD | Polygon、Tiingo、Finnhub、Alpha Vantage | 免费档有限额；付费月费级起步 |
| A 股正规源 | 券商 OpenAPI、合行/数商 EOD 授权、部分云行情 | 通常按年或按量，个人项目偏贵 |
| 基金净值 | 基金公司 / 天天基金类合作，或持牌数据商 | 净值相对易得；商用仍需授权 |

**务实建议**：  
- **MVP = Phase A**：日终拉取 + 本地缓存，接受偶发失败与手动刷新。  
- 上架前再换 **Phase B** 授权源，抽象 `MarketDataProvider` 以便替换。

### 不建议作为 MVP 主依赖

- 未授权的实时推送扒取  
- 要求实名券商账户才能用的接口（可作为后期「券商同步」增强）  
- 同时接 5+ 家源却无统一适配层（维护成本爆炸）

### 架构上的数据适配建议

```
MarketDataProvider (接口)
  ├─ AShareProvider      → Tushare / AkShare
  ├─ HkUsProvider        → yfinance / 后续 Tiingo
  ├─ MutualFundProvider  → AkShare 基金净值
  └─ FxProvider          → 日终汇率
```

本地缓存日 K / 净值，失败时用「上一有效价」并标记数据陈旧。

## 4. 银行存款与理财：低成本接入

银行侧几乎没有面向个人开发者的统一「余额/理财行情」开放 API（需网银/开放银行合作，成本与合规都高）。

### MVP 做法（推荐）

把它们做成 **手动账户资产（ManualAsset）**：

| 类型 | 用户录入 | 系统计算 |
|---|---|---|
| 活期存款 | 余额、币种、可选年利率 | 按日简单计息（可选）或仅记账余额 |
| 定期存款 | 本金、利率、起息日、到期日 | 到期利息；未到期按应计利息（可选） |
| 银行理财 / 货基类 | 本金或份额、当前估值、预期收益率或净值 | 市值以用户更新的估值为准；可提醒「估值已过期」 |
| 现金（钱包） | 余额 | 参与资产占比 |

### 降低手工负担的技巧（仍零接口成本）

1. **余额变更流水**：只记「存入/取出」，余额自动累加  
2. **估值提醒**：理财超过 N 天未更新估值则角标提示  
3. **导入**：后期支持 CSV / 账单粘贴（仍非银行 API）  
4. **货币基金若有公开净值**：可升级为「场外基金」自动估值，从手动账户毕业

### 明确不做（早期）

- 对接各银行 App / 爬取网银  
- 开放银行（Open Banking）多银行聚合  
- 理财产品排行与推荐

## 数据获取总结表

| 资产 | MVP 自动行情 | 用户必须录入 | 备注 |
|---|---|---|---|
| A 股 | ✅ 日终价 | 交易、费用 | 分红尽量自动 |
| 港股 | ✅ 日终价 + 汇率 | 交易、费用 | |
| 美股 | ✅ 日终价 + 汇率 | 交易、费用 | |
| ETF | ✅ 同上市地 | 交易、费用 | |
| 场外基金 | ✅ 净值（可 T+1） | 申赎份额与费用 | |
| 存款/理财 | ❌ | 余额/本金/利率/估值 | 低成本手动账户 |
